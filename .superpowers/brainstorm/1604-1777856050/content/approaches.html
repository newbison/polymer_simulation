Three Approaches for the Polymerization Simulator

All browser-based Canvas animations — differ in architecture and UI polish

A — Single-File HTML

Everything in one .html file: Canvas, JS simulation, and inline CSS controls. Zero dependencies, zero build. Share by sending the file.

Pros

  • Trivial to share (one file)
  • No tools needed to work on it
  • Fastest to build

Cons

  • Messy beyond ~500 lines
  • UI controls will look basic
  • Hard to extend later

B — Modular Vanilla JS (Recommended)

Separate JS modules for simulation engine, rendering, and UI. Clean CSS for polished controls. Served with a simple local server (or just open index.html).

Pros

  • Clean separation of concerns
  • Maintainable & testable
  • Polished UI without framework overhead
  • Still dependency-free

Cons

  • Multiple files to manage
  • Needs ES modules (works in all modern browsers)

C — React + Canvas

React app with a Canvas component for the simulation. Component library for polished sliders, buttons, and panels. Build step with Vite.

Pros

  • Most polished UI possible
  • Component ecosystem
  • Good for complex state

Cons

  • Build tooling required
  • More dependencies
  • Overengineered for a single-canvas app
